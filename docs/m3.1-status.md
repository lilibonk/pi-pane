## 本轮整合修正

- `/login`、`/logout` 在命令目录尚未返回时也能直接打开账户分类；快速粘贴 slash 命令后提交时读取最新草稿，避免被误发为模型消息。
- 浏览器协议升至 v2。已认证的旧 v1 页面只收到它能理解的致命刷新提示，不取得租约、会话或管理状态；刷新加载新页面后正常连接。
- RPC 子进程贯穿生命周期保留宿主 IPC 断开监听，已测时序见下方实报；启动后取消 IPC 对事件循环的保活，避免拖延正常退出。命令回收与关闭钩子的范围仍有异议，见独立审查。
- HOME 被打开为项目时，稳定且存在的自定义 agent/session 根及其别名仍从文件预览、检索和 Git 视图排除。项目根的打开、新建和重新定位限制继续有效；父链接删除/悬空、权限/大小写及请求内改指的例外见 rc.3 独立审查。
- 目录加载结果不会覆盖正在编辑的路径，查询参数改变后不再把上一个目录的结果用于确认操作。
- 登录步骤在可交互前清空上一步输入，避免晚到的页面 effect 清除刚粘贴的密钥；只记住用户已经关闭的结果操作 ID，刷新不重复弹出结果，进行中的步骤仍可恢复。

- 设置草稿与默认主题字段在可交互前完成同步，避免刚选中的值被延后 effect 重置；账户和设置的待应用提示保留真实失败原因，扩展否决不再误报为正在回复。

### 独立审查结论

1. **RPC：同意改善，对无条件清理保证有异议。** 未打开启动门时 pi 未导入，直接退出成立；正常运行时 pi 的 SIGTERM 处理器先同步清理已登记命令；EOF 已开始关闭时处理器已被撤销，空监听器避免 signal-exit 重发信号打断 disposal，但2秒退出仍会跳过尚未完成的清理。门打开后的启动钩子、未被登记的 `pi.exec`、同步阻塞，以及 EOF 后扩展错误写入已关闭 stdout 的提前退出风险，均未得到完整动态覆盖。建议上游提供绑定实际 runtime 的幂等公开命令清理接口，在等待 hook 前执行；深导入内部模块可能取得另一份 PID 登记表，不作为稳定补救。
2. **目录：同意点目录项目恢复，对完整过滤保证有异议。** 稳定的自定义 agent/session 根及别名仍被过滤；整体删除 `alias/custom-sessions`（alias 指向 real）后，保护路径回退为 alias 拼写，Git 缺失目标重建为 real 路径，历史内容被返回；rc.1 同样复现。请求内改指保护根 symlink 后，新实现可返回文件名称/大小，下一次预览被拒绝。后者使用披露的实例调度钩子确定性复现，没有改源码或靠概率重试。
3. **两处等待：同意。** 与 rc.1 源码快照逐行对比，CONC-03 与 E2E-09-TARGET 的断言未改变，仅等待条件改变。前者仍允许另一页直播更新后不再发送；本轮5次实际均有两个请求。后者的完整回复标记与两次稳定读取适用于本确定性夹具，不证明任意扩展以后都不会追加。
4. **界面：待应用原因与死顶栏删除同意；原删除告知有异议。** 此处原静态判断“pi返回无模型、不发送提示”错误，已按rc.3真实页面实测更正：pi1.1.0实际报告`unknown/unknown`占位对象、available0，rc.2原提示会报出占位名；rc.3两条删除重载路径各显示1条正确的“没有可用的模型”提示。列表失败误判和晚连接页面提示丢失等保留异议见rc.3审查。

## 审核后的修正（2026-10-12）

对上面的候选做了一次独立审核，随后修改了源码和脚本。**当前工作区已不同于 `0.3.0-rc.1` 归档**；rc.1的归档、精确安装和安装后闭环结果只对修改前的内容成立，当时需要重新冻结并重跑。本节记录的是重新冻结前的审核状态；当时尚未运行修改后的完整矩阵。rc.2历史结果与rc.3当前结果见上文。

- **宿主崩溃后命令成为孤儿。** 上文“整个生命周期保留 IPC 断开保护”的实现是断开即退出，跳过了 pi 的清理：对照实验中强杀宿主后，pi 正在执行的 shell 命令继续运行。现在断开时调用 pi 自己的终止处理器，不打断 pi 已经开始的关闭，并以 2 秒为上限；启动门打开前仍立即退出。pi 已开始关闭、而关闭钩子超过 2 秒仍未结束时，正在执行的命令仍可能留下，这一情形没有覆盖。新增 5 项单元测试和真实 pi 的 `ORPHAN-COMMAND`、`ORPHAN-COMMAND-HOOK` 两项检查。
- **项目自身位于点目录下时文件面板为空。** 新增的 agent/session 目录过滤连带按绝对路径判断 `.codex`、`.pi` 等名称，`~/.codex/worktrees/…` 这类检出的全部文件被排除。现在绝对路径只用于受保护目录，名称仍按项目内相对路径判断；文件枚举每次只解析一次受保护目录。
- **两处脚本时序。** `m31:concurrency` 的 CONC-03 在第一个页面发出命令后就计数，可能漏掉胜出的请求；`m31:resilience` 的 E2E-09-TARGET 在外部终端写完回复前读取文件。审核重跑时各失败过一次，失败时产品行为正确。两处都改为等待确定的状态，断言未放宽。
- 供应商页的待应用提示改为显示真实失败原因；删除确认的文字与“由 pi 换用其他模型并提示”一致；删除了已无对象的顶栏代码。

审核时在修改前的内容上重跑了此前未完成的 7 组：界面 20/20、终端主题 3/3、整合 20/20、兼容 7/7、性能与主题 5/5 一次通过；并发与故障恢复各有一次上述脚本时序失败，重跑通过。前 17 组没有重跑。
